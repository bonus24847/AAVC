# วัดขอบเขตสนามด้วยตัวโดรนเอง (ground survey)

โจทย์ใหม่จากอาจารย์ (2026-08-14): ใช้ **เต็มสนาม มจพ.** (ขนาดใกล้เคียง
ภารกิจจริง) ขึ้น-ลงที่ **ลู่วิ่งมุมบนซ้าย (NW/W)** เข้า-ออกทางเดียวกัน

พิกัดชุดใหม่จะ **วัดด้วย GPS ของโดรนเอง** ไม่ใช่ลากจากภาพดาวเทียม เพราะ
GPS แบบไม่มี RTK มี **ค่าเบี่ยงคงที่ 1–2.5 m**: ถ้าขอบสนามมาจากภาพ ค่าเบี่ยง
นั้นจะไปอยู่ระหว่าง "แผนที่" กับ "สิ่งที่โดรนคิดว่าตัวเองอยู่ตรงไหน" — geofence
จะเพี้ยนเท่านั้นพอดี แต่ถ้าวัดด้วย**ตัวรับสัญญาณตัวเดียวกับที่บิน** ค่าเบี่ยง
ร่วมนี้จะหักล้างกันเอง: มุมที่โดรนวัด = มุมที่โดรนจะบินไป

## ต้องเตรียม

- โดรนเปิดเครื่อง มี **GPS 3D fix** (ยิ่งดาวเทียมเยอะยิ่งดี — รอ ≥ 10 ดวง)
- ตัวบันทึกต้องเห็นสัญญาณ MAVLink ของ FC — เลือกวิธีตามตาราง

## เลือกวิธีเชื่อมต่อ

| วิธี | ตอนเดินต้องมีสัญญาณไหม | เหมาะเมื่อ |
|---|---|---|
| **① รันบน CM4** (แนะนำ) | **ไม่ต้อง** — CM4 อยู่บนโดรน บันทึกไปด้วยกัน | deploy ขึ้น CM4 แล้ว |
| ② รันบนโน้ตบุ๊กผ่าน Nomad | ต้องมีตลอด (ELRS ถึงทั้งสนาม) | ผ่าน bench checklist MAVLink mode แล้ว |
| ③ รันบนโน้ตบุ๊กผ่าน WiFi | ต้องมีตลอด — **WiFi ไม่ถึงกลางสนาม** ❌ | ใช้ไม่ได้กับงานเดินสำรวจ |
| ④ ต่อสาย USB โน้ตบุ๊ก↔Pixhawk | ไม่ต้อง (แต่ต้องอุ้มโน้ตบุ๊กเดินด้วย) | ยังไม่ได้ตั้ง CM4 |

### ① บน CM4 (ไม่ต้องมีสัญญาณตอนเดิน)

ยืนที่จุด L&R ตอน WiFi ยังถึง แล้ว ssh เข้าไปเริ่มบันทึก:

```bash
ssh aavc@<ip-cm4>
cd ~/mission
env -u PYTHONPATH .venv/bin/python tools/survey_logger.py \
    --url /dev/ttyAMA0 --baud 921600 --out captures/survey_track.jsonl
```
(ถ้ามี mavlink-router รันอยู่แล้ว ใช้ `--url udpin:0.0.0.0:14552` แทนสาย)

จากนั้น**ถอดโน้ตบุ๊กทิ้งไว้ได้เลย** — อุ้มโดรนเดินเก็บทุกมุมตามขั้นตอนข้างล่าง
เสร็จแล้วเดินกลับเข้าระยะ WiFi กด Ctrl-C ในหน้าต่าง ssh เดิม แล้วดึงไฟล์มา:

```bash
scp aavc@<ip-cm4>:mission/captures/survey_track.jsonl captures/
```
⚠ ถ้า WiFi หลุดกลางทาง ssh จะตาย **พร้อมกับตัวบันทึก** — กัน 30 วิด้วย
`tmux` (`ssh aavc@<cm4> -t 'tmux new -s survey'` แล้วค่อยรันคำสั่งข้างใน;
กลับมาต่อด้วย `tmux attach -t survey`)

### ④ ต่อสาย USB (ยังไม่มี CM4 ก็ทำได้)

```bash
env -u PYTHONPATH .venv/bin/python tools/survey_logger.py \
    --url /dev/ttyACM0 --baud 921600
```

## ขั้นตอนหน้างาน (~10 นาที)

1. เริ่มโปรแกรม — จะเห็นบรรทัดสถานะสด (fix / จำนวนดาวเทียม / พิกัด / เวลานิ่ง)
2. **อุ้มโดรนไปยืนที่มุมสนามทีละมุม** แล้ว **ยืนนิ่ง ≥ 30 วินาที** ต่อมุม
   (หน้าจอจะนับ "นิ่งมา … s" ให้เห็น — ครบแล้วค่อยเดินต่อ)
   - แนะนำเดินตามลำดับ: **NW → NE → SE → SW** (ตามเข็ม เริ่มมุมบนซ้าย)
   - ยืนตรงขอบ**ที่ยอมให้โดรนบินถึง** (เช่น ขอบนอกลู่วิ่ง) ไม่ใช่ขอบหญ้า
     ถ้าอยากรวมลู่วิ่ง
3. จุดสุดท้าย: ไปยืนที่ **จุดขึ้น-ลงจริง (L&R)** บนลู่วิ่งมุม NW/W ยืนนิ่ง ≥ 30 วิ
4. กด **Ctrl-C** ปิดโปรแกรม

## แปลงเป็นค่าที่ระบบใช้

```bash
env -u PYTHONPATH .venv/bin/python tools/survey_extract.py \
    captures/survey_track.jsonl --names "NW,NE,SE,SW,LR"
```

จะได้: จุดที่วัดได้ทุกจุด (พร้อมค่ากระจาย + จำนวนดาวเทียม ให้เห็นว่าจุดไหน
วัดไม่ดี), กรอบสนามที่ fit ได้ (จุดศูนย์กลาง + แกน + ขนาด) และ **ค่าคงที่ชุด
พร้อมวางลง `tools/gen_geo.py`**

ไม่มีการเขียนไฟล์อัตโนมัติ — ตามกติกาของโปรเจกต์ (CLAUDE.md §8) ทุกพิกัดใน
ระบบต้องออกจาก `gen_geo.py` ที่เดียว: ตรวจตัวเลขก่อน แล้วให้ gen_geo สร้าง
config / world / launcher / GCS field ใหม่ทั้งชุดพร้อมกัน (invariant จะได้ไม่หลุด)

## ข้อควรระวัง

- **อย่าเดินตัดมุม**: จุดที่ยืนนิ่งเท่านั้นที่ถูกนับ ระหว่างเดินระบบทิ้งอัตโนมัติ
- ยืนนิ่งไม่ถึง 20 วิ = จุดนั้นหาย (ปรับได้ด้วย `--dwell`)
- ค่ากระจายเกิน 1.5 m = สัญญาณไม่ดีพอ ยืนเพิ่มอีกหน่อยหรือรอดาวเทียมมากขึ้น
- ถ้าใช้ค่าจากการวัดคนละวันมาปนกัน ค่าเบี่ยงจะไม่หักล้าง — **เก็บทุกจุดในรอบเดียว**
- ความสูงจาก GPS ไม่ใช้ (เพดานบินอ้างจากพื้นตอน takeoff เสมอ)
