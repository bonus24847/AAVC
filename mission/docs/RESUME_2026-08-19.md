## 2. รอ operator ตัดสิน — ผมไม่ทำเองเพราะแตะความปลอดภัย/ฮาร์ดแวร์

### 2.1 ⚠ `BAT1_V_CHARGED` ชนกันระหว่างสองรีโป (โดรนลำเดียวกัน)

```
config ของเซสชันข้างบ้าน : 4.15
พินของรีโปนี้            : 4.05
```
**ใครรัน preflight ทีหลังเขียนทับ** ต้องเคาะให้ตรงกันก่อนซ้อมวันเดียวกัน
เหตุผลที่เขายกมาและหนักแน่น: เที่ยวบิน E ของเขา (17 ส.ค.) แตะ floor 30 % ที่ 540 s
โดยปล่อยไข่ครบที่ 480 s ⇒ **margin เหลือ ~60 วินาที** ไม่มีที่ให้เกจคลาด 10 จุด
⇒ ตัดสินไม่ได้จนกว่าจะอ่าน `V_EMPTY` จริง (ข้อ 1)

### 2.2 ย้ายการกัน PILOT TAKEOVER ไปที่ชั้นคำสั่ง

ตอนนี้กันที่ตัวจับ exception (`emergency_recover`, commit `1672b09`) ซึ่ง**ได้ผลจริง**
พิสูจน์สดแล้ว แต่ข้างบ้านกันที่ชั้นคำสั่ง (`Drone._guard()` raise จากทุก method ที่
ขยับเครื่อง) ซึ่งปิดช่องได้ที่ต้นทาง — ของเราถ้ามีคำสั่งอื่นถูกส่งระหว่างที่ loop
ค้างอยู่ ยังหลุดได้ ข้อสำคัญที่เขาย้ำ: **flag ต้องอยู่ที่อ็อบเจกต์ที่เป็นเจ้าของการส่ง
(`DroneCommander`) ไม่ใช่ที่ mission loop**

### 2.3 แบต 17000 mAh semi-solid (มาถึงแล้ว 19 ส.ค.)

**ยังไม่เปลี่ยน** และคำแนะนำคืออย่าเปลี่ยนก่อนปิด G7 — แพ็ค 7500 ผ่านการตรวจครบและ
ระบบทั้งชุด validate มากับมัน ถ้าเปลี่ยนตอนนี้ เที่ยวบินจริงเที่ยวแรกจะมีตัวแปรใหม่
ห้าตัวพร้อมกัน สิ่งที่ต้องขยับพร้อมกันถ้าจะเปลี่ยน:

| อะไร | ตอนนี้ | ต้องทำ |
|---|---|---|
| `battery.capacity_mah` | 7500 | → 17000 |
| `seed_sortie_mah` / `seed_delivery_mah` | 1750 / 900 | คิดใหม่ ไม่ใช่คูณ — แพ็คหนักขึ้น กินกระแสมากขึ้นต่อวินาที |
| AUW / `MPC_THR_HOVER` | 8.22 kg (2 แพ็ค) | **ต้องชั่งจริง** ค่า +2.1 kg เดิมเป็นการประมาณ ไม่มีใครชั่ง |
| `BAT1_V_EMPTY` / `V_CHARGED` | 3.50 / 4.15 (LiPo) | ⚠ **เคมีคนละแบบ** ต้องได้สเปกจากผู้ผลิต |

⚠ ไม่มีกระแสมาช่วย เกจทั้งอันคือ `interpolate(cell_v, V_EMPTY, V_CHARGED)` ⇒ ใส่
endpoints ของ LiPo ให้ semi-solid = เกณฑ์ RTH/LAND ไปตกที่แรงดันผิด และ**แยกจาก
อาการไม่ออกจนกว่าจะสาย**

ก่อนแตะตัวเลข ต้องมี: **น้ำหนักแพ็คที่ชั่งจริง + น้ำหนักรวมทั้งลำ + สเปกแรงดัน
(เต็ม/ตัดล่าง ต่อเซลล์) + แรงดันพักหลังชาร์จเต็มที่วัดด้วยมัลติมิเตอร์**
